# 📖 Documentação — Finance Tracker (Supabase)

Sistema de controle financeiro pessoal para estudantes internacionais na
China: duas moedas (RMB/XOF), 4 idiomas, tema claro/escuro, layout
mobile-first e relatórios em PDF. Python + Streamlit, com **Supabase
(Postgres)** como banco de dados.

---

## 1. Visão Geral

| Item | Detalhe |
|---|---|
| Arquivo principal | `finance_tracker.py` (app em um único arquivo) |
| Interface | [Streamlit](https://streamlit.io) (≥ 1.66) |
| Banco de dados | Supabase (Postgres) via biblioteca `supabase` |
| Gráficos | Plotly |
| PDF | `fpdf2` |
| Moedas | RMB (¥) primária · XOF (Franco CFA) secundária (padrão 1 RMB = 85 XOF, ajustável) |
| Idiomas | 🇬🇧 English · 🇵🇹 Português · 🇫🇷 Français · 🇨🇳 中文 |
| Uso previsto | Uma pessoa, principalmente pelo celular |

Os dados ficam no Supabase, fora do servidor do app. Por isso o app pode ser
hospedado em plataformas gratuitas (que apagam arquivos locais a cada
reinício) sem perder nada.

---

## 2. Arquitetura

```
 Celular / PC ──HTTPS──► App Streamlit ──HTTPS (API REST/PostgREST)──► Supabase Postgres
 (navegador)             finance_tracker.py     chave SECRETA (só no servidor)
```

- O navegador **nunca** fala com o banco: só com o app. A chave secreta fica
  nos *secrets* do Streamlit.
- O Streamlit reexecuta o script a cada interação; toda leitura/escrita passa
  pelas funções da Seção 5.
- Não há login: quem tiver o link do app usa os mesmos dados (ver Seção 8).

## 4. Modelo de dados

Seis tabelas no schema `public`. As colunas `id` são `bigint` geradas pelo
Postgres (`generated by default as identity`) — o app **não** calcula ids.

### `income`
| Coluna | Tipo | Observação |
|---|---|---|
| `id` | bigint, PK | automático |
| `date` | date | |
| `source` | text | uma das 4 fontes (valor canônico em inglês) |
| `amount_rmb` | numeric(14,2) | ≥ 0 |
| `notes` | text | opcional |

### `expenses`
| Coluna | Tipo | Observação |
|---|---|---|
| `id` | bigint, PK | automático |
| `date` | date | |
| `category` | text | uma das 10 categorias (com emoji, em inglês) |
| `description` | text | opcional |
| `amount_rmb` | numeric(14,2) | ≥ 0 |
| `payment_method` | text | Alipay / WeChat Pay / Cash / Bank Card |

### `budgets`
| Coluna | Tipo | Observação |
|---|---|---|
| `category` | text, PK | mesma lista de `expenses.category` |
| `limit_rmb` | numeric(14,2) | ≥ 0; 0 = sem limite |

### `bills`
| Coluna | Tipo | Observação |
|---|---|---|
| `id` | bigint, PK | automático |
| `bill_name` | text | |
| `amount_rmb` | numeric(14,2) | ≥ 0 |
| `due_date` | date | |
| `status` | text | `Pending` ou `Paid` (há `CHECK` no banco) |
| `date_paid` | date | `NULL` se pendente |

### `goals`
| Coluna | Tipo | Observação |
|---|---|---|
| `id` | bigint, PK | automático |
| `goal_name` | text | |
| `target_amount` | numeric(14,2) | ≥ 0 |
| `current_amount` | numeric(14,2) | ≥ 0 |
| `deadline` | date | |

### `settings` (chave → valor, sempre texto)
`exchange_rate`, `savings_goal_monthly`, `theme`, `language`, `initialized`
(flag interna: o app só grava os padrões uma vez).

> **Valores canônicos × exibição.** Categorias, fontes, métodos de pagamento
> e status são gravados **sempre em inglês**; só a *exibição* é traduzida
> (`tr_option`). Assim, trocar de idioma nunca quebra somas nem filtros.

## 5. Camada de acesso a dados

| Função | O que faz |
|---|---|
| `get_supabase()` | Cria o cliente (cacheado por processo) com `supabase_url` + `supabase_key` |
| `fetch_df(tabela)` | Lê a tabela inteira **paginada de 1000 em 1000** (o limite padrão da API é 1000 linhas), ordenada por `id`/chave, e devolve um `DataFrame` já tipado |
| `insert_row(tabela, dict)` | Insere uma linha (o Postgres gera o `id`) |
| `update_row(tabela, id, dict)` | Atualiza só as colunas informadas |
| `delete_row(tabela, id)` | Exclui por `id` |
| `upsert_row(tabela, dict, coluna_conflito)` | Insere ou atualiza (usado em `settings` e `budgets`) |
| `get_setting` / `get_float_setting` / `set_setting` | Configurações; a versão `float` tolera valor vazio/inválido e usa o padrão |
| `ensure_database_ready()` | Uma vez por sessão: grava padrões (câmbio, orçamentos, 4 contas fixas) |
| `_py(valor)` | Converte tipos numpy para Python puro antes de enviar como JSON |

Diferenças em relação à versão com Google Sheets: sem `next_id` (o banco
numera), sem buscar o número da linha (atualiza/exclui direto por `id`), e
cada gravação é uma operação atômica no Postgres.

## 6. Funcionalidades por página

- **🏠 Dashboard** — saldo atual; receita, despesa e saldo do mês (RMB + XOF);
  barra da meta mensal (🟢 ≥70% · 🟡 40–70% · 🔴 <40%); pizza por categoria;
  linha de gasto diário.
- **💵 Income** — cadastro, histórico em tabela, exclusão (o seletor mostra
  *data · fonte · valor*).
- **🧾 Expenses** — cadastro, histórico, edição e exclusão.
- **📊 Monthly Budget** — limite por categoria e barra de uso:
  🟢 <70% · 🟡 70–90% · 🔴 >90%.
- **📌 Bills** — cartões por conta, troca Pendente/Pago (grava a data de
  pagamento), exclusão, total pendente.
- **🎯 Savings & Goals** — metas com barra de progresso, botão para somar
  valor guardado, exclusão.
- **📄 Reports** — qualquer mês/ano: resumo, gráfico por categoria, 5 maiores
  despesas, aderência ao orçamento, contas e metas, e **PDF** para baixar.
  *Limitação:* o PDF usa fontes padrão (sem 中文); a tela em chinês funciona
  normalmente.

### Barra lateral
Idioma, tema, taxa de câmbio, meta mensal, exportar CSV (receitas/despesas)
e link para o painel do Supabase.

### Mobile-first
Sidebar recolhida automaticamente em telas pequenas; botões e campos com
altura mínima de 44 px; ajustes de fonte/espaçamento em 768 px e 480 px;
contas em formato de cartão (sem rolagem horizontal); colunas empilhadas.

## 8. Segurança e privacidade

- **Chave secreta** (`sb_secret_...`): acesso total ao banco; fica só nos
  secrets do servidor. Nunca no GitHub, em prints ou no navegador. Se
  vazar, gere outra em *Project Settings → API Keys* e atualize os secrets.
- **RLS ativado, sem políticas**: a chave *publishable* (pública) não
  consegue ler nem gravar nada. Só a chave secreta (que ignora RLS) acessa.
- **Sem login no app**: qualquer pessoa com o link vê e edita os mesmos dados.
  Mantenha o link privado, ou adicione autenticação (ex.: `st.login` do
  Streamlit ou `streamlit-authenticator`) — não incluída para manter o
  projeto simples.
- **Backups**: o plano grátis do Supabase não inclui backups diários
  gerenciados. Use *Exportar CSV* na barra lateral de vez em quando.

## 9. Limitações conhecidas

| Limitação | Detalhe |
|---|---|
| **Pausa por inatividade** | Plano grátis pausa o projeto após 7 dias sem atividade (dados preservados; restaurar no painel). Mitigação: `keepalive.yml` ou uso semanal |
| Limites do plano grátis | 500 MB de banco, 2 projetos ativos, 5 GB de tráfego — de sobra para uso pessoal |
| Sem login / um usuário | Ver Seção 8 |
| PDF sem 中文 | Fonte padrão do PDF |
| Sem anexos | Não guarda fotos de recibos |
| Categorias fixas | Definidas no código (listas no topo do arquivo) |

## 10. Testes e depuração

`python tests/e2e_test.py` roda o app com Streamlit `AppTest` contra um
Supabase **simulado em memória** (sem internet): carrega as 7 páginas, cria
receita/despesa/orçamento/meta, edita e exclui, alterna conta paga (com data
automática), troca entre os 4 idiomas e gera o relatório/PDF.

Verificações feitas durante o desenvolvimento:
- sintaxe do SQL validada com o parser real do Postgres;
- assinaturas da biblioteca `supabase` conferidas (`upsert(on_conflict=...)`,
  `order`, `range`, aceita chaves `sb_secret_...`);
- paginação testada com 2.500 linhas (soma correta);
- avisos de depreciação removidos (`use_container_width` → `width="stretch"`,
  `ln=True` → `new_x/new_y` no `fpdf2`);
- todos os payloads enviados são JSON-serializáveis (`_py`).

## 11. Solução de problemas

Veja a tabela completa em `SETUP.md`. Os três casos mais comuns: projeto
**pausado** (Restore no painel), **secrets errados** (URL sem barra final +
chave secreta inteira) e **SQL não executado** (`relation ... does not exist`).

## 13. Glossário

- **RMB (¥)** — yuan chinês. **XOF** — franco CFA da África Ocidental.
- **RLS (Row Level Security)** — regras do Postgres que limitam quem lê/grava cada linha.
- **Secret key / publishable key** — chaves de API do Supabase: a secreta é
  de servidor (acesso total); a publishable é pública (limitada por RLS).
- **PostgREST** — a API REST que o Supabase expõe sobre o Postgres.
- **Secrets (Streamlit)** — variáveis privadas injetadas em tempo de execução.
